# 菜单与业务场景

本文件说明命令行界面（CLI）的菜单结构、角色权限和操作场景。菜单只负责收集输入、调用业务接口和展示结果；账号是否存在、角色是否有权、卡是否冻结、余额是否足够等规则全部由 [业务服务接口](../include/services/) 执行。隐藏菜单项不能代替接口内的授权检查。

公共入口和金额解析契约见 [cli.h](../include/cli.h)。数据目录、JSON 格式与索引规则见 [存储格式与查询契约](storage-schema.md)。

## 顶层流程

1. 程序启动后由入口初始化存储，CLI 先调用 `auth_needs_bootstrap` 查询初始化状态。
2. 查询失败时只提示错误并结束，不把存储错误当成“首次启动”。
3. 确实没有有效账号时进入管理员初始化流程；已有账号或并发创建成功时直接进入登录菜单。
4. 未登录菜单只提供“登录”和“退出”两项。
5. 登录成功后保存认证服务返回的会话快照，按会话角色显示对应菜单。
6. 退出登录只清除本地会话并回到未登录菜单；修改本人密码后会话继续有效。
7. 读取到 EOF 时正常结束程序；输入输出流故障返回 `APP_ERR_IO`。

### 程序入口与会话

- 入口 `main` 负责初始化存储、调用 `cli_run`、关闭存储；CLI 不直接调用存储函数或读写 JSON。
- 数据目录固定为启动工作目录下的 `data`；测试使用独立临时目录。
- 登录成功后保存认证服务返回的 `Account` 会话快照，退出登录时清除；修改密码成功后继续使用当前会话。
- 卡用户的充值、消费和修改电话只使用会话中的关联学号，界面不提供目标学号输入。
- 后端实现尚未接入时，入口明确提示无法启动并返回失败，不伪造登录或业务成功。

### 未登录菜单

```text
==== 校园卡管理系统 ====
1. 登录
0. 退出
```

首次启动时先显示管理员初始化：输入用户名、密码和确认密码。界面不预置固定密码，也不主动打印、记录密码或凭据。

### 管理员菜单

```text
==== 管理员菜单 ====
当前用户：<用户名>
1. 创建账号
2. 查询账号
3. 列出账号
4. 删除账号
5. 修改本人密码
0. 退出登录
```

### 卡用户菜单

```text
==== 卡用户菜单 ====
当前用户：<用户名>
1. 查询本人卡与余额
2. 修改联系电话
3. 充值
4. 消费
5. 修改本人密码
0. 退出登录
```

充值、消费和修改电话不提示输入学号，目标学号由服务层从会话中取得，因此界面无法把操作指向其他学生。

### 卡业务员菜单

```text
==== 卡业务员菜单 ====
当前用户：<用户名>
1. 开卡
2. 按学号查询
3. 按姓名查询
4. 冻结卡
5. 解冻卡
6. 修改本人密码
0. 退出登录
```

按姓名查询逐条显示全部精确同名结果，不把同名视为唯一记录。

## 权限矩阵

| 操作 | 未登录 | 管理员 | 卡用户 | 卡业务员 | 服务接口 |
| --- | --- | --- | --- | --- | --- |
| 创建首个管理员 | 仅首次启动 | — | — | — | `auth_bootstrap_admin` |
| 登录 | 是 | — | — | — | `auth_login` |
| 修改本人密码 | — | 是 | 是 | 是 | `auth_change_password` |
| 创建账号 | — | 是 | — | — | `account_create` |
| 查询账号 | — | 是 | — | — | `account_get` |
| 列出账号 | — | 是 | — | — | `account_list` |
| 删除账号 | — | 是（不能删除自己） | — | — | `account_delete` |
| 开卡 | — | — | — | 是 | `card_issue` |
| 按学号查询卡 | — | — | 仅本人 | 任意学号 | `card_get_by_id` |
| 按姓名查询卡 | — | — | — | 是 | `card_find_by_name` |
| 修改联系电话 | — | — | 仅本人 | — | `card_update_own_phone` |
| 充值 | — | — | 仅本人 | — | `card_recharge` |
| 消费 | — | — | 仅本人 | — | `card_consume` |
| 冻结或解冻 | — | — | — | 是 | `card_set_status` |

表中“仅本人”由服务层根据会话中的 `student_id` 判断，界面不提供目标学号输入。管理员没有校园卡业务权限；卡用户没有开卡、查询他人和冻结权限；卡业务员没有账号管理、充值和消费权限。越权调用即使绕过菜单也必须由服务层返回 `APP_ERR_PERMISSION_DENIED`。

## 输入与展示约定

- 每项输入读取整行并去掉行尾换行符；空行对菜单选择视为无效，对可空字段（电话）视为空字符串。
- 超长行排空当前行后再提示，残留字符不会成为下一次选择。字段长度超过模型容量时同样提示并返回菜单。
- 界面文本使用 UTF-8；Windows 启动时把控制台输入输出代码页设置为 UTF-8。
- 密码输入可以回显，但界面不主动打印、记录密码或凭据；密码缓冲区用后清零。
- 账号只显示用户名、角色和关联学号，不显示盐、派生值或完整 `Account`。
- 金额输入经 `cli_parse_amount` 解析为整数分，整数按元换算（例如 `1` 表示 1.00 元），最多两位小数；展示固定两位小数，全程不使用浮点数。
- 金额允许解析零，零金额充值和消费由服务层拒绝。金额格式错误在界面提示，不调用业务接口。
- 错误提示只根据返回码生成，不显示内部绝对路径、密码盐、派生值或堆栈。

### 金额格式

`cli_parse_amount` 只接受 ASCII 数字和可选的小数点，整数部分至少一位，小数部分最多两位。整数输入表示元，例如 `1` 换算为 100 分；`1.2` 换算为 120 分，`1.23` 换算为 123 分。允许输入 `0`，零金额充值和消费由业务服务拒绝。

| 输入 | 结果 |
| --- | --- |
| `0`、`00`、`0.0` | 成功，0 分 |
| `1`、`1.2`、`1.23` | 成功，分别 100、120、123 分 |
| `+1`、`-1` | 拒绝：正负号 |
| `1.234`、`.5`、`1.` | 拒绝：小数格式错误 |
| `1e3`、`1,000` | 拒绝：指数或逗号 |
| 前后或中间空格 | 拒绝：空白 |
| 超出 `INT64_MAX` 分 | 拒绝：转换溢出，`out_cents` 保持原值 |

展示余额时由整数分格式化为固定两位小数，例如 5 分显示为 `0.05` 元，全程不使用浮点数。

### 输入边界

- 空行在菜单选择中视为无效选择；电话号码等可空字段收到空字符串。
- EOF 正常结束程序；EOF 前没有换行符的最后一行仍按完整一行处理。
- 超长行会排空到本行末尾，然后提示“输入过长”，残留字符不会成为下一次选择。
- CRLF 行尾会去掉 `\r`，不会把回车字符当作字段内容。
- 输入输出流故障返回 `APP_ERR_IO`；密码、盐、派生值和内部路径不会出现在提示中。

### 错误提示

| 返回码 | 界面提示 |
| --- | --- |
| `APP_OK` | 操作成功并在需要时显示结果 |
| `APP_ERR_INVALID_ARGUMENT` | 输入不合法 |
| `APP_ERR_NOT_FOUND` | 记录不存在 |
| `APP_ERR_ALREADY_EXISTS` | 记录已存在 |
| `APP_ERR_AUTH_FAILED` | 用户名或密码错误 |
| `APP_ERR_PERMISSION_DENIED` | 没有执行该操作的权限 |
| `APP_ERR_INSUFFICIENT_BALANCE` | 余额不足 |
| `APP_ERR_CARD_FROZEN` | 校园卡已冻结 |
| `APP_ERR_IO` | 读写失败 |
| `APP_ERR_INVALID_DATA` | 数据损坏 |
| `APP_ERR_NO_MEMORY` | 内存不足 |

业务错误提示后留在当前菜单，可由用户继续操作；读写失败、数据损坏和内存不足视为无法继续，提示后退出当前流程。EOF 不视为错误。

## 业务场景

以下数据均为虚构。场景应使用独立临时数据目录运行，避免污染演示数据。

1. **首次启动**：无账号时创建管理员；创建成功后用同一用户名和密码登录。重启后不再出现初始化入口。
2. **创建业务员**：管理员创建角色为卡业务员的账号，关联学号为空。
3. **开卡**：业务员依次输入学号、姓名、性别、院系、班级和可空电话；成功后余额为零、状态正常。
4. **创建关联卡用户**：管理员创建卡用户账号，关联学号必须是已开卡学号；未开卡时服务返回 `APP_ERR_NOT_FOUND`。
5. **本人卡操作**：卡用户查询自己的卡和余额，修改电话，充值后余额增加，消费后余额减少。
6. **冻结与解冻**：业务员冻结卡后，卡用户充值或消费返回 `APP_ERR_CARD_FROZEN`；解冻后恢复。冻结期间仍可修改电话。
7. **同名查询**：为两名姓名完全相同的学生开卡，业务员按姓名查询时两条记录都显示，界面不能只保留一条。
8. **修改密码**：任意已登录角色验证旧密码后设置新密码；会话继续有效，退出后用旧密码登录失败。
9. **删除账号**：管理员删除其他账号；被删除账号不能登录，对应学生卡记录仍然保留。管理员不能删除当前登录账号。
10. **输入边界**：空行、连续无效选择、EOF、超长行和非法金额都不应破坏会话或把残留输入当成下一次选择。
11. **损坏数据**：账号计数或读取遇到损坏记录时提示数据损坏并退出，不进入首次初始化，也不把余额显示为零。
