# 存储格式与查询契约

本文件定义存储层读写的数据格式。模型容量及错误码以 [common.h](../include/common.h) 和 [models.h](../include/models.h) 为准，接口及资源所有权以 [storage.h](../include/storage.h) 为准。JSON 由 yyjson 统一处理，业务层和界面层不自行生成 JSON。

## 编码与格式判定

记录文件使用 UTF-8，不带 BOM，顶层必须是对象。下表列出的字段全部必需，不接受缺字段、重复键、额外字段或 `null`。键名和枚举字符串区分大小写，字段排列和排版空白不影响含义。不接受注释、尾随逗号或对象之后的其他内容。

字符串长度按 JSON 解码后的 UTF-8 字节计算，不含 C 字符串末尾 NUL。拒绝非法 UTF-8 和字符串内部的 NUL，包括转义形式的 NUL；不对姓名做 Unicode 规范化、大小写转换或空白裁剪。所有字符数组写入模型时必须补 NUL，不允许截断后当作合法数据。

读取格式不符的数据返回 `APP_ERR_INVALID_DATA`；保存时模型字段不合法返回 `APP_ERR_INVALID_ARGUMENT`。文件不存在返回 `APP_ERR_NOT_FOUND`，系统读写失败返回 `APP_ERR_IO`，分配失败返回 `APP_ERR_NO_MEMORY`。模型和标量输出只在成功时写入，失败保持原值。列表输出必须已经初始化为空，失败时清理构造中的结果并保持空表。

## 学生与校园卡主记录

| JSON 字段 | 类型 | 约束 |
| --- | --- | --- |
| `student_id` | 字符串 | 九位 ASCII 数字，必须与文件路径对应的学号一致 |
| `name` | 字符串 | 非空 UTF-8，不超过 `NAME_MAX_BYTES` |
| `sex` | 字符串 | 仅允许 `男`、`女`、`其他` |
| `department` | 字符串 | 非空 UTF-8，不超过 `DEPARTMENT_MAX_BYTES` |
| `class_name` | 字符串 | 非空 UTF-8，不超过 `CLASS_NAME_MAX_BYTES` |
| `phone` | 字符串 | 可空，不超过 `PHONE_MAX_BYTES`；非空时仅允许 ASCII 数字、加号、连字符和空格 |
| `balance_cents` | 整数 | 从零到 `INT64_MAX`，单位为分；拒绝小数及指数写法，即使数值上等于整数 |
| `status` | 字符串 | `active` 对应正常，`frozen` 对应冻结 |

主记录示例使用虚构数据：

```json
{
  "student_id": "251543201",
  "name": "张三",
  "sex": "男",
  "department": "计算机学院",
  "class_name": "示例班",
  "phone": "",
  "balance_cents": 1250,
  "status": "active"
}
```

每名学生最多一张卡，卡号等于学号，不额外保存卡号字段。开卡由业务层强制设置零余额和正常状态；存储保存接口允许覆盖合法主记录，不负责判断是否重复开卡。

## 账号记录

| JSON 字段 | 类型 | 约束 |
| --- | --- | --- |
| `username` | 字符串 | 非空，不超过 `USERNAME_MAX_BYTES`；仅允许 ASCII 字母、数字、下划线、连字符和点，必须与文件名解码得到的用户名一致 |
| `password_salt` | 字符串 | 长度为 `PASSWORD_SALT_HEX_LENGTH`，仅允许小写十六进制字符，对应模型的 `password_salt_hex` |
| `password_hash` | 字符串 | 长度为 `PASSWORD_HASH_HEX_LENGTH`，仅允许小写十六进制字符，对应模型的 `password_hash_hex` |
| `role` | 字符串 | `admin`、`card_user`、`card_clerk`，分别对应管理员、卡用户、卡业务员 |
| `student_id` | 字符串 | 卡用户必须为九位 ASCII 数字；其余角色必须为空字符串 |

账号不保存明文密码、迭代次数或算法名称。密码派生采用公共密码接口约定，参数以公共常量为准，不引入不同账号使用不同算法的机制。

存储层检查账号字段本身的格式，不检查关联卡是否存在；创建账号时由业务层确认卡用户关联的是已开卡学号。账号列表和认证会话中的凭据只能在程序内部使用，不能整体打印或记录。

## 目录与主键

正常运行的数据根目录为启动工作目录下的 `data`，通过 `storage_init` 传入。测试传入独立临时目录。以下路径均相对于该数据根目录。

| 内容 | 路径规则 |
| --- | --- |
| 账号 | `accounts/<用户名的 Base64URL 编码>.json` |
| 学生主记录 | `students/<两位>/<两位>/<两位>/<一位>/<两位>.json` |
| 姓名索引 | `indexes/name/<每两个编码字符一级目录>/<学号>` |

Base64URL 对原始字节编码，使用 URL 安全字母表，不保留末尾 `=`。用户名使用 ASCII 字节，姓名使用 UTF-8 字节。姓名编码长度不是偶数时，最后一级目录保留剩下的一个字符。

学号 `251543201` 对应 `students/25/15/43/2/01.json`。用户名 `student001` 对应 `accounts/c3R1ZGVudDAwMQ.json`。姓名“张三”编码为 `5byg5LiJ`，对应目录 `indexes/name/5b/yg/5L/iJ`，其中学号索引项的文件名为 `251543201`，文件内容为空且不添加扩展名。

路径只能由已校验的键生成，不直接拼接原始用户输入。按学号和用户名读取均直接定位，不扫描全部记录。列表枚举不保证顺序；不符合规定路径形状的条目不作为记录加载，位于合法记录路径但内容损坏的文件必须报错，不能跳过后伪装成空目录。

## 姓名查询与索引维护

主记录是权威数据，姓名索引仅用于定位。查询先枚举姓名目录中的九位数字普通文件，再加载主记录并按原始字节比较姓名。非法索引文件名及非普通文件跳过，主记录不存在或姓名不符时跳过；主记录损坏、目录读取失败或其他系统错误必须传播。

姓名目录不存在、目录为空或所有索引均失效，统一返回 `APP_OK` 和空列表。目录存在但不是目录返回 `APP_ERR_IO`。这项约定优先于单记录读取的“文件不存在返回未找到”。

开卡先保存主记录，再创建空索引项。已有同名空索引项返回成功；同位置为非空文件或其他类型条目返回 `APP_ERR_INVALID_DATA`，不截断覆盖。保存主记录不会自动追加索引，业务层负责调用顺序。

任一步失败都可能已经留下部分文件，不保证回滚。不实现自动修复、索引重建、原子提交或并发写入保护。

## 初始化与账号计数

`storage_init` 创建账号、学生和姓名索引根目录。存储操作要求已初始化，再次初始化前先关闭；`storage_shutdown` 幂等，只释放内存。

账号计数使用与账号列表一致的合法路径及数据校验，发现损坏账号立即返回数据错误，不把它当作没有账号。初始化成功后必需根目录若被外部删除，操作返回存储错误，不能据此重新创建管理员。

业务层通过 `auth_needs_bootstrap` 查询是否需要首次管理员初始化。CLI 仅调用业务接口；入口只负责存储生命周期。查询成功且没有账号时才显示初始化流程，查询失败时提示错误，不进入初始化。创建首个管理员时再次检查账号数量，已有账号返回 `APP_ERR_ALREADY_EXISTS`。
