# 文件访问与存储验证

## 实现与职责

`file_access` 封装文件类型判断、实际目录比较、递归建目录、非递归枚举、路径拼接、二进制读写和删除。Windows 使用 UTF-16 文件系统接口，在边界转换 UTF-8 路径；POSIX 使用目录与文件接口。枚举不跟随符号链接，回调名称仅在当前调用期间有效。读文件分配的缓冲区由调用方使用 `file_access_free` 释放，写入检查关闭结果。

`storage` 只通过文件访问接口操作磁盘，使用 yyjson 解析和生成 JSON。保存前检查模型；读取时检查对象字段集合、重复键、字符串、枚举、金额以及路径与主键的一致性。余额必须是非负整数分；小数、指数写法和越界整数均不能作为合法余额。读取失败时，模型与标量输出保持原值；列表构造失败时释放已分配节点。

路径、字段与合法示例以 [存储格式与查询契约](storage-schema.md) 为准。学号查询直接生成路径，不扫描全部记录。账号文件名采用用户名原始 ASCII 字节的小写十六进制，保留大小写区分的同时避免在不区分大小写的文件系统上产生文件名碰撞，大小写不同的用户名可独立共存。读取、覆盖和删除均核对文件内的实际用户名，主键不符时返回数据错误。姓名索引通过无填充 Base64URL 编码定位目录，单项追加须核对主记录姓名；全量检查通过 `file_access_same_directory` 比对实际目录推导缺项与过期项，显式修复在预检通过后补建缺项并清理过期空索引文件，不删除目录。

初始化后必需根目录若被删除或替换为文件，存储接口返回错误，不能触发首次管理员创建。关闭只释放进程内的路径状态，不改写文件。保存主记录与追加姓名索引是独立操作，业务层先保存再追加；任何一步失败都可能留下部分数据，不提供回滚、自动修复或并发写入保障。

## 自动测试

测试目标及注册信息见 [CMakeLists.txt](../CMakeLists.txt)。使用 README 中的依赖与构建步骤，完成构建后运行：

```sh
ctest --test-dir build --output-on-failure
ctest --test-dir build -R '^(file_access|storage|storage_services)$' --output-on-failure
```

| 测试 | 验证内容 |
| --- | --- |
| `test_file_access` | 空文件和跨缓冲区二进制读写、中文路径、重复建目录、同一实际目录比较、非目录冲突、容量不足、输入输出重叠、回调中止、不存在路径及输出保持；POSIX 下另测符号链接与权限拒绝 |
| `test_storage` | 账号十六进制小写路径、大小写不同用户名共存与删除隔离、文件内主键严格核对；主记录往返、删除、计数、列表、直接定位；单项姓名索引主记录校验与追加；全量索引只读检查与显式修复（补缺项、只清理规范目录形状中的过期空索引、预检损坏主记录或被占用路径时阻断写入）；同名多结果、无命中索引；严格 JSON 校验、主键不符、错误类型、重复或额外字段、非法 UTF-8/NUL、金额边界、根目录异常、关闭后重新初始化 |
| `test_storage_services` | 真实存储与业务接口联调：首次管理员、登录、创建大小写不同账号共存、开卡、充值消费、冻结解冻、修改电话和密码、删除账号不删除卡、损坏账号阻止管理员初始化 |

测试只在自行创建的临时目录中使用虚构资料，成功后清理目录。发生断言失败时保留目录便于排查；不得把这些数据作为正式演示数据提交。测试中的固定字符串只用于验证，不是程序默认账号或密码。

可以在 Clang 构建中增加 `-fsanitize=address,undefined -g`，由运行时检查越界访问及未定义行为。测试结果只覆盖实际执行的平台；POSIX 权限测试在非 root 用户下执行，Windows 权限模型需另行验证。

格式与静态检查使用根目录的 `.clang-format` 和 `.clang-tidy`。对存储相关实现、测试源码及测试辅助文件执行 `clang-format --dry-run --Werror`；对存储相关 C 源码执行 `clang-tidy --warnings-as-errors='*'`，并检查测试辅助源码及头文件。第三方依赖作为系统头文件，编译参数使用本机实际的 C23、SDK 和依赖路径。平台规定的功能开关宏保留标准名称，并对保留标识符检查作局部说明。

## 验证范围与限制

验证应在目标平台上分别执行 CMake 配置、构建、CTest 和实际启动流程，并在 PR 中记录实际平台、依赖来源及未执行项。仓库文档不保存某次验证环境的版本或一次性结果。

依赖及锁定版本以 [vcpkg.json](../vcpkg.json) 为准。使用未按清单安装依赖的构建不能视为锁定依赖验证。

自动测试不等同于 POSIX 与 Windows 两端的文件系统验证。交接时需在目标平台完成 README 中的构建和上述 CTest 命令，特别检查中文目录、目录枚举、权限错误及重启读取。现有测试未注入全部内存分配、磁盘耗尽或文件关闭失败，不把这些测试视为这些故障的全面验证。

## 交接与演示

业务层可直接调用 [storage.h](../include/storage.h)，不需要拼路径或处理 JSON；查询返回的链表由调用方使用对应的 `*_list_clear` 释放。UI 根据错误码展示提示，不能将读取失败解释成零余额、无账号或正常首次启动。

程序入口使用真实文件存储，数据目录为启动工作目录下的 `data`。演示可从一个空的专用目录启动程序，通过 CLI 创建管理员、业务员、学生卡和卡用户，再完成充值与消费。退出后从同一目录再次启动，展示账号及余额仍可读取。演示与测试均不使用真实个人资料，报告引用格式、索引原理和测试结果即可，不提交运行数据或二进制文件。
