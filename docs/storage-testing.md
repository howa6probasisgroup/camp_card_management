# 文件访问与存储验证

## 实现与职责

`file_access` 封装文件类型判断、递归建目录、非递归枚举、路径拼接、二进制读写和删除。Windows 使用 UTF-16 文件系统接口，在边界转换 UTF-8 路径；POSIX 使用目录与文件接口。枚举不跟随符号链接，回调名称仅在当前调用期间有效。读文件分配的缓冲区由调用方使用 `file_access_free` 释放，写入检查关闭结果。

`storage` 只通过文件访问接口操作磁盘，使用 yyjson 解析和生成 JSON。保存前检查模型；读取时检查对象字段集合、重复键、字符串、枚举、金额以及路径与主键的一致性。余额必须是非负整数分；小数、指数写法和越界整数均不能作为合法余额。读取失败时，模型与标量输出保持原值；列表构造失败时释放已分配节点。

路径、字段与合法示例以 [存储格式与查询契约](storage-schema.md) 为准。用户名和学号查询直接生成路径，不扫描全部记录。列表只遍历规定形状的路径，合法记录路径中的损坏数据返回错误。姓名索引通过 Base64URL 编码定位目录，再根据索引文件名读取主记录并核对原始姓名字节；姓名相同不意味着学号唯一，因此返回全部有效同名记录。

初始化后必需根目录若被删除或替换为文件，存储接口返回错误，不能触发首次管理员创建。关闭只释放进程内的路径状态，不改写文件。保存主记录与追加姓名索引是独立操作，业务层先保存再追加；任何一步失败都可能留下部分数据，不提供回滚、自动修复或并发写入保障。

## 自动测试

测试目标及注册信息见 [CMakeLists.txt](../CMakeLists.txt)。使用 README 中的依赖与构建步骤，完成构建后运行：

```sh
ctest --test-dir build --output-on-failure
ctest --test-dir build -R '^(file_access|storage|storage_services)$' --output-on-failure
```

| 测试 | 验证内容 |
| --- | --- |
| `test_file_access` | 空文件和跨缓冲区二进制读写、中文路径、重复建目录、非目录冲突、容量不足、输入输出重叠、回调中止、不存在路径及输出保持；POSIX 下另测符号链接与权限拒绝 |
| `test_storage` | 账号和主记录往返、删除、计数、列表、直接定位、同名多结果、无命中和过期索引；严格 JSON 校验、主键不符、错误类型、重复或额外字段、非法 UTF-8/NUL、金额边界、根目录异常、关闭后重新初始化 |
| `test_storage_services` | 真实存储与业务接口联调：首次管理员、登录、创建账号、开卡、充值消费、冻结解冻、修改电话和密码、删除账号不删除卡、损坏账号阻止管理员初始化 |

测试只在自行创建的临时目录中使用虚构资料，成功后清理目录。发生断言失败时保留目录便于排查；不得把这些数据作为正式演示数据提交。测试中的固定字符串只用于验证，不是程序默认账号或密码。

可以在 Clang 构建中增加 `-fsanitize=address,undefined -g`，由运行时检查越界访问及未定义行为。测试结果只覆盖实际执行的平台；POSIX 权限测试在非 root 用户下执行，Windows 权限模型需另行验证。

## 已执行验证与限制

在 macOS arm64 上完成了 CMake 配置和整个项目构建，启用严格警告、AddressSanitizer 和 UndefinedBehaviorSanitizer。逐个运行 CTest 注册的测试可执行文件，全部成功且没有 sanitizer 报错；公共头文件逐个通过独立语法检查。

该环境使用 yyjson 0.13.0 源码及可用的 OpenSSL 3.6.2 动态库进行验证，依赖放在仓库外，未更改 vcpkg 清单。没有执行清单指定的 OpenSSL 版本安装，因此不能把本次构建视为锁定依赖的完整验证。环境中有 CMake，但没有 CTest 驱动程序；已运行的是其注册的全部测试程序，尚未验证 `ctest` 驱动命令本身。

还运行了两次独立的正式 CLI 进程：第一次完成管理员初始化、创建业务员、开卡、创建卡用户、充值 100 元和消费 12.50 元；退出后第二次启动，使用同一临时数据目录登录并查到 87.50 元余额。测试结束后清理了该目录。

Windows 分支尚未编译或运行。交接时需在 Windows 完成 README 中的构建和上述 CTest 命令，特别检查中文目录、目录枚举、权限错误及重启读取。没有注入所有内存分配、磁盘耗尽或文件关闭失败，不把现有测试视为这些故障的全面验证。

## 交接与演示

业务层可直接调用 [storage.h](../include/storage.h)，不需要拼路径或处理 JSON；查询返回的链表由调用方使用对应的 `*_list_clear` 释放。UI 根据错误码展示提示，不能将读取失败解释成零余额、无账号或正常首次启动。

正式入口默认启用真实存储，数据目录为启动工作目录下的 `data`。演示可从一个空的专用目录启动程序，通过 CLI 创建管理员、业务员、学生卡和卡用户，再完成充值与消费。退出后从同一目录再次启动，展示账号及余额仍可读取。演示与测试均不使用真实个人资料，报告引用格式、索引原理和测试结果即可，不提交运行数据或二进制文件。
