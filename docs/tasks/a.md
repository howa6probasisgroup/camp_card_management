# 成员 A 的任务

你负责文件访问与存储，让业务层能够通过统一接口读取、保存和查询数据。开发分支使用 `member/a/<任务>`，通过 PR 合并到 `main`。接口以仓库中的 [file_access.h](../../include/file_access.h) 和 [storage.h](../../include/storage.h) 为准，协作流程见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 路径与数据格式

整理账号、学生主记录和姓名索引的路径规则，交付存储设计说明。学号只接受九位 ASCII 数字，按两位、两位、两位、一位、两位拆分目录与文件名；用户名经 Base64URL 编码并去除填充后用作账号文件名；姓名按 UTF-8 原始字节进行同样编码，每两个编码字符构成一级索引目录。

明确主记录与账号 JSON 的字段、类型、长度、枚举和数值范围。使用 yyjson 统一解析和序列化，余额始终保存为整数分，角色与卡状态保存为约定字符串。姓名索引文件以学号命名，内容为空。把路径示例、合法数据示例和非法数据判定写入存储说明，不引入额外的数据模型。

与 B 核对模型和错误码，与 C 核对运行目录、测试目录及面向用户的错误含义。业务层不得自行拼路径，界面不得直接解析 JSON。

## 跨平台文件访问

实现 `src/file_access.c`，完成递归建目录、条目类型判断、目录枚举、路径拼接、整文件读取、直接写入、文件删除和读取缓冲区释放。Windows 与 macOS 的平台差异集中在本模块，存储层不直接调用平台专属目录 API。

按头文件处理回调借用期、缓冲区容量、内存所有权和空指针约定。区分文件不存在与系统读写失败，检查读写及关闭结果。目录枚举不递归、不返回点目录、不跟随符号链接，回调失败时停止并传播错误。

为文件访问增加独立测试，覆盖空文件、不存在路径、目录已存在、同名非目录、容量不足、回调中止和正常读写删除。平台相关行为分别在 Windows 与 macOS 验证，记录实际结果。

## 账号与主记录存储

实现 `src/storage.c`，完成存储初始化与关闭、账号读取保存删除列表计数、主记录读取保存列表，以及按姓名查询和索引追加。

初始化复制数据目录并创建所需子目录。测试使用独立临时目录；正常运行使用启动工作目录下的数据目录。关闭只释放内存，不额外写盘。

读取时检查必需字段、字段类型、字符串长度、枚举、数值范围及文件路径与主键是否一致。缺失文件返回未找到，损坏记录返回数据错误，不能把读取失败转成零余额或空账号目录。保存接口允许创建或覆盖，重复账号和重复开卡由 B 在业务层拒绝。

姓名查询先枚举索引，再读取主记录并比较姓名原始字节。跳过合法索引指向的缺失主记录和姓名不符记录，传播主记录损坏与读写失败。没有命中时返回成功的空列表。索引不自动修复，不增加重建菜单。

使用 B 提供的链表承接列表结果，成功后交由调用方清理，失败时清理已构造结果。直接写入文件，不增加临时文件替换、事务回滚、文件锁或崩溃恢复。

## 存储验证与交接

交付存储测试源码及测试说明，覆盖模型往返读写、账号删除、主记录直接定位、全部记录枚举、同名多结果、无命中、过期索引、损坏 JSON、缺字段、错误类型、非法枚举、数值越界及目录读写错误。确认账号计数遇损坏数据不会错误触发首次管理员初始化。

将新增源码和测试接入 CMake 与 CTest，与其他成员协调构建文件的修改。交给 B 可实际调用的存储实现、独立测试命令和错误语义；交给 C 数据目录用法、虚构演示数据准备方法及平台验证结果。对失败后可能留下的主记录或索引如实说明，不承诺回滚。

## 集成、报告与答辩

参与完整业务联调，负责排查路径、序列化、目录遍历、索引命中和持久化问题。验证程序重启后账号与余额仍可读取，测试不会污染演示数据。

提供最终报告中的文件布局、JSON 格式、索引原理、文件访问设计和存储测试材料；检查对应源码注释。为答辩准备文件定位与同名查询的说明，协助演示重启后的数据读取。

提交前检查仓库不包含真实账号、密码、运行数据或本机绝对路径。最终材料的二进制文件不提交到仓库，向整理最终成果的成员提供所需文字和验证记录。
