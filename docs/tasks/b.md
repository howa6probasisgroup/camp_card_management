# 成员 B 的任务

你负责公共数据模型、链表、密码处理和业务服务，让每项操作在接口内部执行正确的校验与授权。开发分支使用 `member/b/<任务>`，通过 PR 合并到 `main`。公共接口以 [include](../../include/) 下的头文件为准，协作流程见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 公共模型与接口

维护公共常量、错误码、角色、卡状态、学生输入、主记录和账号模型。明确字符串长度按字节计算、末尾 NUL、学号格式、金额范围、输出参数和资源所有权。每个公开声明的文档注释只描述该声明，使用中文并确保 IDE 能正确识别。

与 A 核对存储格式和错误语义，与 C 核对业务入参、输出和角色权限。需要调整签名、字段、所有权或权限规则时，通过 PR 组织三人确认，并同步实现、调用方和测试。业务层不拼路径、不调用文件 API、不处理 JSON 细节。

## 链表与基本操作

维护 `src/data_structures.c` 和 [data_structures.h](../../include/data_structures.h)，完整承担三类链表的实现、验证和使用说明。

- `StudentList`：初始化、追加学生主记录副本、按学号查找、按学号删除、计数、清理。
- `AccountList`：初始化、追加账号副本、按用户名查找、按用户名删除、计数、清理。
- `StringList`：初始化、复制字符串并去重追加、判断字符串是否存在、计数、清理。

学生与账号列表维护尾指针，使追加为常数复杂度；查找和删除按链表顺序执行，重复键命中首项。字符串列表按原始字节比较，重复追加成功但不新增节点。列表拥有模型和字符串副本，调用方修改原值不影响节点。查找返回列表内部的借用指针，在对应节点删除或列表清空后失效。

保持空表、空指针、重复清理和清空后复用的约定。分配失败不破坏原列表，审查所有分配失败路径，保证资源仍可释放。不要让链表承担字段合法性、角色权限或业务去重。

维护 `tests/test_data_structures.c`，覆盖空表、追加顺序、头中尾查找与删除、不存在元素、重复键、副本独立性、字符串去重、尾指针更新和批量操作。提供数据结构说明，解释复杂度、所有权、借用期和测试方法。仓库已有链表实现及测试，应逐项核对契约并补足缺口。

## 密码与认证

实现 `src/password.c`，使用 OpenSSL Crypto 生成随机盐并执行 PBKDF2-HMAC-SHA-256，参数以公共常量为准。盐与派生值保存为小写十六进制，校验时使用恒定时间比较，不保存或输出明文密码。

实现认证服务，完成首次管理员创建、登录和修改本人密码。只有不存在有效账号时才允许初始化管理员，损坏账号不得视为空目录。不存在用户名和错误密码统一返回认证失败，存储损坏和读写错误分别传播。修改密码须验证旧密码，生成新盐和派生值，成功后当前会话继续有效。

为密码和认证增加独立测试，覆盖长度边界、错误密码、非法盐与派生值、重复初始化、旧密码错误及换密后旧密码失效。测试输出不得包含密码或凭据。

## 账号与校园卡业务

实现账号服务，支持管理员创建、查询、列出和删除账号。创建前查重，卡用户关联已开卡学号，其他角色使用空关联学号。拒绝删除当前登录账号，删除其他账号不删除学生卡记录，也不增加最后一个管理员保护机制。

实现校园卡服务，支持开卡、按学号查询、按姓名查询、修改本人电话、充值、消费、冻结和解冻。开卡只接收学生信息，强制零余额和正常状态，先保存主记录再追加姓名索引。重复学号拒绝覆盖。

每个业务接口自行校验调用者。卡业务员负责开卡、查询和冻结解冻；卡用户只能访问绑定卡片并修改本人电话、充值与消费；管理员没有卡业务权限。充值和消费只从调用者取学号，金额必须为正整数分，冻结卡禁止资金操作，检查余额不足与加法溢出。重复设置同一卡状态返回成功且不改余额。

金额解析由 C 负责，业务层仍须拒绝非法分值。普通业务校验失败不得修改数据，文件写入失败则遵循存储层不保证回滚的边界。

## 业务验证与交接

交付业务测试源码和测试说明，覆盖所有角色的允许与禁止操作、空参数、字段边界、重复用户名和学号、未开卡关联、自删限制、越权访问、冻结状态、零负金额、余额不足和溢出。检查失败输出和列表清理符合接口约定。

与 A 联调真实存储，并验证开卡部分失败、账号损坏和文件读写失败的传播。与 C 核对首次启动、登录、换密和退出会话流程。存储尚未就绪时可使用仅限测试目标的替代实现验证业务规则，最终须以真实存储运行结果完成验收。

将实现与测试接入 CMake 和 CTest，避免与正式实现重复链接。交给 C 可调用的服务、角色限制和错误结果示例，交给 A 需要持久化的模型与操作顺序。

## 集成、报告与答辩

参与完整业务联调，负责定位权限、字段校验、状态、余额和密码问题。检查 UI 不能绕过服务授权，账号查询结果不会把凭据显示出来。

提供最终报告中的模型、链表、密码、业务规则和业务测试材料，检查公开接口与源码注释。准备数据结构基本操作、三种角色边界和整数金额计算的答辩说明，协助演示冻结消费失败及换密后的登录行为。

与 A、C 共同审查阶段材料和最终报告，向整理最终成果的成员提供可复现的测试记录，不把未执行的平台验证写成已通过。
